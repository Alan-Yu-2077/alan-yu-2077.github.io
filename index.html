About

I build things that feel like someone's there. Luna is a companion, not an assistant — she remembers, she starts conversations on her own, she has a face and a voice. She also has no installer, on purpose: she's one person's companion, and the instance that matters lives on one machine.

What I can't help is the detail nobody asked for. The wordmark up there is a voxel block, tumbling on three axes, rendered per frame into character cells small enough that a stroke still reads solid. The character field behind this text thins out wherever there are words to read. Nobody would have noticed if I'd skipped either one.

I build with AI in the loop and I'm not quiet about it — but every version I ship carries a written note on what changed and why, including the ones that were wrong. Going fast and knowing exactly what you shipped are the same discipline. I also fix other people's things — including airi, the closest thing Luna has to a rival and some 50,000 stars ahead of her. It's all MIT. Take what's useful.

Stack

Agent runtime & scheduling
State-machine turn loops with bounded tool iteration · three-state concurrency (safe-parallel / session-serial / global-serial) · conversation state persisted to SQLite and rebuilt on restart · proactive behaviour gated by deterministic rails — quiet hours, idle floor, cooldown, quota · full-turn tracing with a local timeline viewer.
Tool execution & isolation
Zod validation of every tool call's input and output · per-tool timeouts and abort signals, and one ok/err ToolResult · path guards that canonicalize before every check, and an evaluator firewall over the files that gate the agent · SSRF-guarded outbound fetch, pinned to the checked IP · origin-checked transport, loopback by default.
Production engineering
Strongly-typed full-stack TypeScript · one Zod-typed wire contract shared by server and client, so an unmirrored change is a compile error · a supervisor that restarts a crashed backend · every risky feature behind a default-off flag before its default flips · a written rationale per release.

Going deeper on — multi-agent scheduling under contention, stronger isolation boundaries for tool execution (MicroVM and Wasm runtimes), distributed scheduling across agent workers, and durable execution / workflow-replay engines. Direction, not shipped work — the isolation above is in-process.

Languages & runtime — TypeScript (strict) · Python · C++ · Go · Bun · Node · Electron · SQLite · WebSocket · MCP · Anthropic & OpenAI-compatible providers · Git · Docker
