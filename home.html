About

I work on the layer underneath the agent. I don't train or fine-tune models — the LLM is a black box I call over a wire, and everything around that call is the part I own: the state machine that drives a turn, the dispatcher that runs its tools under timeouts and abort signals, the sandbox that decides what those tools may touch, and the store that lets a long task survive a restart.

agent-kernel is that layer on its own — a StateGraph turn loop, a Zod-first registry that validates every tool call at runtime, three-state concurrency so two tools that must never overlap can't, and full-turn tracing you can read in a local viewer. Luna is where it was extracted from; holdem-arena is what happened when I pointed the same core at a table of agents playing each other. Luna's sandbox has one rule I'm fond of: she may read the files that judge her — the tests, the lint config, the shell deny-regex, the sandbox itself — but she may never write them.

I build with AI in the loop and I'm not quiet about it — but every version I ship carries a written note on what changed and why, including the ones that were wrong. Going fast and knowing exactly what you shipped are the same discipline. I also fix other people's things — including airi, the closest thing Luna has to a rival and some 46,000 stars ahead of her. It's all MIT. Take what's useful.

Stack

Agent runtime & scheduling
State-machine turn loops with bounded tool iteration · multi-agent async scheduling under contention · three-state concurrency (safe-parallel / session-serial / global-serial) · long-horizon state persisted to SQLite and resumed from checkpoint · proactive behaviour on deterministic rails rather than timers · full-turn tracing and replay.
Tool execution & isolation
Runtime type validation at the tool boundary (Zod-first registry, no as) · per-tool timeouts, abort signals and a unified Result<T> · capability sandboxing with canonicalized paths and an evaluator firewall over the files that gate the agent · SSRF-guarded outbound fetch · origin-checked transport, loopback by default.
Production engineering
Strongly-typed full-stack TypeScript · one Zod-typed wire contract shared by server and client, so an unmirrored change is a compile error · fault-tolerant recovery and async event-loop decoupling · every risky feature behind a default-off flag before its default flips · a written rationale per release.

Going deeper on — stronger isolation boundaries for tool execution (MicroVM and Wasm runtimes), distributed scheduling across agent workers, and durable execution / workflow-replay engines. Direction, not shipped work — the sandboxing above is in-process.

Languages & runtime — TypeScript (strict) · Python · C++ · Go · Bun · Node · Electron · SQLite · WebSocket · MCP · Anthropic & OpenAI-compatible providers · Git · Docker

Projects

  • agent-kernel — a persona-free agent runtime

    The runtime with the personality taken out. A generic StateGraph turn loop (parse → build → stream → dispatch → append → finalize, capped at eight tool iterations), a Zod-first defineTool factory whose registry validates every call at runtime, and a dispatcher with three-state concurrency — safe-parallel, session-serial, global-serial — under per-tool timeouts, abort discipline and one unified Result<T>. Every turn traces to SQLite and reads back in a local viewer. Add tools, swap the system prompt, and it is a different agent.

    • TypeScript
    • Zod
    • Concurrency
    • Tracing
    • SQLite

  • Luna — the long-running agent the kernel came from

    An agent that has to survive restarts. Three layers of memory over one SQLite file with hybrid recall and a relevance floor, an offline consolidation pass that distills a day into durable facts and reusable skills, and proactive scheduling behind deterministic rails instead of a timer. Tool access goes through a capability sandbox with canonicalized paths and an evaluator firewall — she may read the tests, lint config and shell deny-regex that gate her, never write them — and web access is SSRF-guarded. Server and client share one Zod-typed WebSocket contract, so a wire change not mirrored on both sides is a compile error.

    • TypeScript
    • Bun
    • SQLite
    • Sandboxing
    • WebSocket
    • Electron
